# 信息差发现平台 — 端到端需求文档

## 1. 产品概述

### 1.1 产品定位
一个帮助用户**跨越语言、地域、信息圈层**发现"信息差"的内容聚合平台，聚合国内优惠、海外精品、投资机会、实用工具等多维度信息。

### 1.2 核心价值
- **跨语言信息差**：使用 AI 做价值判断，找到优质文章。AI 判断依据**可配置化**（评分权重、分类规则、关键词过滤等均可由管理员调节），自动翻译海外英文/日文/韩文优质内容为中文
- **跨地域信息差**：聚焦**成都**本地，聚合同城优惠、机会和投机信息
- **跨圈层信息差**：打通微信公众号、抖音、小红书、同城信息平台、本地论坛等圈层

### 1.3 目标用户
- **普通用户**：寻找优惠、发现海外好物、获取实用工具
- **投资者/创业者**：发现海外创业项目、投资机会、行业趋势
- **管理员**：审核用户提交内容，管理数据源

### 模块 D：AI 智能评估系统（代码存在，需要实现）

#### D0 AI 质量保证体系

AI 不只是简单搬运内容，而是**有依据地评估内容和平台质量**。

| 评估维度 | 说明 | 配置项（管理员可调） |
|---------|------|-------------------|
| **平台信用分** | 每个数据源（source）有信用评级，数据源质量决定内容基础分 | 各源初始分、扣分阈值 |
| **内容质量分** | AI 评估：信息密度、真实性、时效性、相关性 | 各维度权重可调 |
| **价值评分** | score 0-100，综合平台信用 + 内容质量 + 用户互动 | 评分公式可配置 |
| **分类规则** | 内容自动归类到不同分类体系 | 分类关键词表可维护 |
| **关键词过滤** | 黑名单词库自动拦截低质/垃圾内容 | 黑/白名单词库可维护 |
| **审核策略** | 高评分内容自动通过，低评分进人工审核 | 自动通过分数线可调 |

所有 AI 评估结果都会记录**评估依据**，管理员可在后台查看"为什么这条内容得了这个分"。

#### D1 流水线流程

```
爬虫推送 → 分类(classify) → 打分(score) → 摘要(summary) → [海外]翻译(translate) → 存储
```

#### D2 DeepSeek API 调用

| 服务 | 输入 | 输出 |
|------|------|------|
| 分类 classify | content + context(deal/global/opportunity) | category, tags[], summary(100字), score(0-100) |
| 翻译 translate | content + targetLang(zh) + style | titleCn, contentCn, summaryCn |

#### D3 待解决的问题

| 问题 | 风险 | 方案 |
|------|:----:|------|
| DeepSeek API Key 未配置 | 🔴 | 需要在 application.yml 配置 DEEPSEEK_API_KEY |
| JSON 解析用字符串硬解析 | 🟡 | 应改为 Jackson/ObjectMapper 安全解析 |
| WebClient block() 同步调用 | 🟡 | 当前 OK，但可考虑异步优化 |
| 无重试/降级机制 | 🟡 | 需添加 retry + fallback |
| 无 API 调用缓存 | 🟢 | 相同内容重复调用浪费 token |

### 模块 G：用户发帖系统（待开发 ⬜）

用户发帖是平台的**社交 Feed 层**，用户可以自由发布内容，形成瀑布流信息墙。

#### G1 功能定义

| 功能 | 说明 | 优先级 |
|------|------|:----:|
| 瀑布流 Feed | 无限滚动，按时间倒序展示帖子 | P0 |
| 图文发帖 | 用户可发布文字 + 图片（支持多图） | P0 |
| 链接分享 | 用户可附加外链，自动抓取 OG 信息展示卡片 | P0 |
| 分类筛选 | Feed 可按分类/标签筛选 | P1 |
| 互动（点赞/评论） | 基础社交互动 | P1 |
| 用户主页 | 查看某个用户的所有发帖 | P2 |

#### G2 发帖流程

```
用户打开发帖页面 → 填写内容（文字/图片/链接）
                          ↓
                    AI 自动分类 + 打标签 + 质量评分
                          ↓
                    ┌──── 评分判断 ────┐
                    ▼                   ▼
              评分高（自动通过）     评分低或不确定
                    │                   │
                    ▼                   ▼
              出现在 Feed 流        进入人工审核队列
                                        │
                                  管理员审核通过/拒绝
```

#### G3 审核策略（AI + 人工混合）

| 场景 | 处理方式 |
|------|---------|
| AI 评分 ≥ 80 | 自动通过，直接出现在 Feed |
| AI 评分 50-79 | 标记"需人工确认"，进审核队列 |
| AI 评分 < 50 | 自动拦截或进入严格审核 |
| 含敏感词/图片 | 强制人工审核 |

审核依据会记录：AI 给出了什么评分、依据是什么、人工审核员是否采纳。

#### G4 图片存储策略

| 阶段 | 方案 |
|:----:|------|
| 当前 | 本地存储（上传至服务器本地目录） |
| 后期 | 迁移至阿里云 OSS / 腾讯云 COS |

#### G5 与 Submit 爆料的区别

| 维度 | Submit 爆料 | 用户发帖 |
|------|-----------|---------|
| 目的 | 向平台提供线索/信息 | 在平台分享内容/观点 |
| 内容去向 | 转为 Deal/Global/Opportunity/Tool | 独立 Feed 流展示 |
| 审核方式 | 管理员审核后入库 | 瀑布流直接展示（先发后审或先审后发） |
| 用户身份 | 任何用户 | 登录用户 |
